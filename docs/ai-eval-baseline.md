# AI 품질 평가 기준선 (OpenAI gpt-6-luna)

페르소나 적용 품질 평가(`npm run persona:eval`)의 기준선 기록이다. 프롬프트나 모델을 바꾸면 같은 명령으로 다시 돌려 이 표와 비교한다.
평가 케이스는 고정된 예시 상황이며 일기·사용자 데이터는 들어 있지 않다. 평가 리포트 원문(`eval-results/`)은 git 에 올리지 않으므로, 비교에 필요한 숫자는 이 문서에 옮겨 적는다.

## 1. 설정

| 항목 | 값 |
| --- | --- |
| 모델 | `gpt-6-luna` (기본값) |
| API | Responses API, `text.format` json_schema strict |
| reasoning.effort | `low` (기본값) |
| temperature | 보내지 않음 |
| store | `false` |
| 실행 일시 | 2026-11-12 10:25 (KST) |
| 코드 | feature/openai-migration (main 에 #22 로 병합) |
| 평가 구성 | 케이스 13개 x 상사 유형 4개 = 52호출, 동시 2호출, 평가자(`--judge`) 사용 |
| 평가 명령 | `npm run persona:eval -- --judge --interval 3000` |

## 4. 알려진 한계

실패 6건:

- **근거 실재 실패 4건** (케이스 4·IA, 7·DA, 8·DC, 9·IA): `persona_basis` 에 해당 상사 프로필에 적혀 있지 않은 성향을 근거로 쓴 경우다. 평가자는 결과 중시, 용건 확인 선호, 세부 수정 중시, "한 번의 지적만으로는 괴롭힘으로 단정하지 않는다"는 판단을 프로필에 없는 내용으로 지적했다.
- **상사별 해석 차이 실패 2건** (케이스 9, 10): 상사 유형마다 해석이 달라야 하는데, 의미상 서로 비슷한 해석만 나왔다. 두 케이스 모두 발언 의도가 애매한 상황이다.

## 5. 다음 개선 후보

- **persona_basis 를 프로필에 적힌 항목만 쓰게 하는 규칙 강화.** 시스템 프롬프트에 이미 같은 취지의 규칙(근거는 프로필 안의 내용만)이 있는데도 4건이 어겼다. 문장을 더 강하게 쓰거나, 프로필 항목 목록에서 골라 쓰게 하는 방식을 검토한다.
- **평균 응답 6초 대응.** 사용자 화면에 로딩 표시와 재시도(실패 시 다시 보내기)가 필요하다. 필요하면 `OPENAI_REASONING_EFFORT=none` 으로 지연이 줄어드는지, 답변 품질이 유지되는지 같은 명령으로 비교한다.
- **메시지 길이 지시 보강.** 경고 10건이 전부 길이 초과이므로, 제안 메시지 길이 상한을 프롬프트에 더 분명히 쓴다.
- **상사별 해석 차이 개선.** 애매한 발언 케이스(9, 10)에서 상사 유형별 해석 차이가 드러나도록 프롬프트나 예시를 보강한다.

## 6. 이전 기준(Gemini 3.5 flash-lite, 생각 수준 LOW)과 비교

비교 대상은 같은 52호출 구성으로 돌린 마지막 전체 실행이다(2026-10-24 03:13 KST, 평가자 사용).

| 항목 | Gemini (이전) | gpt-6-luna (이번) |
| --- | --- | --- |
| 호출 / 실패 | 52 / 0 | 52 / 0 |
| 평균 응답 시간 | 6.8초 (1.7 ~ 18.4초) | 6.0초 (3.5 ~ 8.1초) |
| 통과 / 실패 / 경고 / 수동 확인 | 409 / 4 / 5 / 5 | 407 / 6 / 10 / 0 |
| 안전 케이스 11~13 true | 12/12 | 12/12 |
| 일반 케이스 1~10 false | 40/40 | 40/40 |
| 케이스 9 false | 4/4 | 4/4 |

- 안전 케이스 결과는 같다.
- 평균 응답 시간은 비슷하고, 최장 응답이 짧아졌다(18.4초 → 8.1초). 최단은 길어졌다(1.7초 → 3.5초).
- 달라진 점: 법적 단정 경고 5건 → 0건, 메시지 길이 경고 0건 → 10건, 상사별 해석 차이 실패 0건 → 2건. 근거 실재 실패는 4건으로 같다. 이전 실행에서 수동 확인이던 항목(5건)은 이번에는 평가자가 모두 판정했다.
- 주의: 이전 실행은 평가 기준과 프롬프트 보강(#19) 병합 전에 돌린 것이라 프롬프트가 완전히 같다고 보장할 수 없다. 응답 시간에는 호출 간격 대기와 재시도 대기가 포함되고, 이전 실행은 모델 호출이 60회(재시도 포함)였다.

## 7. 재평가 방법

프롬프트나 모델(`OPENAI_MODEL`), reasoning(`OPENAI_REASONING_EFFORT`)을 바꾸면 같은 명령으로 다시 돌린다.

```bash
npm run persona:eval -- --judge --interval 3000
```

1. `.env` 에 `OPENAI_API_KEY` 가 있어야 한다. 키는 문서나 로그에 남기지 않는다.
2. 결과는 `eval-results/report.md` 에 저장된다. 이 파일은 git 에 올리지 않는다.
3. 결과 요약, 안전 기준, 실패·경고 목록을 이 문서의 2~4절과 비교한다.
4. 아래 "기록"에 날짜, 설정, 숫자를 추가한다. 리포트 원문은 복사하지 않고 숫자와 항목 이름만 적는다.

기록에 추가할 형식:

```
### YYYY-MM-DD (모델, reasoning, 변경 사유)
- 호출 N건(실패 N), 평균 N초(최소~최대)
- 통과 N / 실패 N / 경고 N / 수동 확인 N
- 안전: 11~13 true N/12, 1~10 false N/40, 케이스 9 false N/4
- 실패·경고 변화: ...
```
